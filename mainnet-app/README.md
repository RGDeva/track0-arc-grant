# Track0 Arc Mainnet review candidate

This is an unpublished, source-hard-disabled Mainnet app candidate, separate from the [live read-only Testnet viewer](https://track0-arc-grant-viewer.vercel.app/). It presents owner-confirmed demo terms (not transaction authorization), an explicit MetaMask connection button, read-only Arc RPC balance/nonce/fee checks, exact unsigned deployment/approval/execute reviews, and a fail-closed evidence view. The public review build substitutes disabled stubs for both the sender and signing-wallet adapter. **No transaction-send code is shipped in that build.** A separate private review build includes the real sender but remains hard-disabled and must not be published. No Mainnet payout is claimed.

Build from the project root with `npm run build:mainnet-review`; inspect `dist-mainnet-review/` and run `npm run audit:mainnet-review`. For the private sender inspection, build with `vite build --config vite.mainnet.activation-review.config.ts` and run `node scripts/assert-mainnet-activation-review-safe.mjs`. The app must not be published as a functioning payment app until a reviewed activation diff, accepted review basis, funded wallet, live gas ceilings and separate transaction authorizations exist. The review/activation references and financial ceilings are deliberately `null`; both grant and global hard-disable flags remain true. The owner confirmed control of the three demo accounts for preparation, not as independent payees or cryptographic proof.

The read-only `?tx=<hash>&contract=<address>` view works without a wallet or browser journal. A URL is only a locator: the page checks the frozen runtime and exact immutable Mainnet terms before using the shared canonical receipt/event verifier. It cannot claim a Mainnet payment until a real transaction passes those checks. A subsequently approved official contract address should be pinned in a separate source review before public release.

The source repository is a Studio recovery workspace and is **not** itself the sanitized public repository. A public release must include only reviewed application source, frozen contract/tests, build configuration, license, accurate README and evidence instructions; omit `.arc-studio/`, local evidence, credentials, traces and internal Track0 customer code. Public GitHub publication, Vercel deployment and grant submission require separate approval.
